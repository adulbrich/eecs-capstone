# ONID OIDC Sign-In Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ONID as a sign-in provider through Better Auth's `genericOAuth` plugin against the Oregon State Entra ID tenant, mapping identity from the ID token with a UPN fallback for the missing email claim, and rewrite `docs/ONID-SSO.md` from a request-stage document into an operations one.

**Architecture:** The only non-obvious piece is `src/lib/onid-profile.ts`. Better Auth's default `getUserInfo` takes the ID-token path only when both `sub` and `email` are present and otherwise falls through to Microsoft Graph's userinfo endpoint, which carries neither the tenant-custom `username` claim nor, for these users, an email. That makes the default unusable for exactly the case UIT warned about. Extracting the mapping into a pure `(idToken: string) => OnidProfile | null` gives us the fallback and gives the test suite something to reach, since nothing else in this change is testable without a live tenant.

**Tech Stack:** Better Auth 1.6 (`genericOAuth` server plugin, `genericOAuthClient` client plugin), TanStack Start / Router, React 19, Vitest, Terraform.

**Spec:** `docs/superpowers/specs/2026-08-24-onid-oidc-design.md`

## Task 1: The profile mapper

- [ ] Write `src/lib/onid-profile.ts` exporting `onidProfileFromIdToken(idToken: string)`.
- [ ] Decode the payload with `Buffer.from(part, "base64url")`. Do not add `jose`; see the spec for why signature verification is not required on the back-channel token.
- [ ] Return `null` for anything that is not a three-part JWT, does not base64url-decode, does not parse as JSON, is not a plain object, or lacks `sub`. Returning `null` makes Better Auth emit `user_info_is_missing` rather than creating a broken account.
- [ ] Email: `email` claim, then `username` claim, then `null`.
- [ ] Name: `given_name` plus `family_name`, then `name`, then the local part of the email.
- [ ] `emailVerified: true` unconditionally, with a comment naming it as an assertion and saying what it is grounded in.
- [ ] Write `src/lib/__tests__/onid-profile.test.ts` covering every case in the spec's Testing section, including `email_verified: false` being deliberately overridden.
- [ ] `npm test` green.

## Task 2: Server configuration

- [ ] `src/lib/auth.ts`: import `genericOAuth` from `better-auth/plugins`, add it to `plugins`.
- [ ] Config: `providerId: "onid"`, `discoveryUrl`, `clientId`, `clientSecret` from `ONID_*` env, `scopes: ["openid", "profile", "email"]`, `pkce: true`, `getUserInfo` delegating to Task 1.
- [ ] No `offline_access`. We call no API on the user's behalf.

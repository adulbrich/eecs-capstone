# Bedrock review goes through the `bedrock-mantle` endpoint signed by hand; embeddings sit behind a flag

The AI review and the scope assessment call the OpenAI-compatible Responses API on `bedrock-mantle`, signed with SigV4 by a hand-written client, because no AWS SDK client exists for that endpoint. The OpenAI SDK with a long-lived Bedrock API key was rejected because it puts a model credential in the task definition, where SigV4 keeps production on the task role. Every call sends `store: false`, since proposals carry unpublished IP and the endpoint otherwise retains inputs for thirty days. Embeddings use `bedrock-runtime` through the SDK, and the two paths share almost nothing. Embeddings sit behind `BEDROCK_EMBEDDINGS_ENABLED`, and the integration suite refuses to start unless it arrived as `false`, because a fail-open reaches the SDK credential chain and pays an IMDS probe that presents as a slow, flaky test.

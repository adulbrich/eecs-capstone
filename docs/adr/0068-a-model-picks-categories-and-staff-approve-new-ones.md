# A model picks a project's categories, and staff approve any new one

A project's categories are picked by a model from the live list in one Mantle tool call whose schema holds each type's category ids as a closed set and its cap, with `strict` on (#31). Proposers do not set categories (#322), and staff authoring them for 100+ projects a term was the bottleneck; keywords scored 0.62 to 0.76 recall on 146 projects and near chance on the old Type facet, where the model does well enough for staff to correct rather than author. It runs on submit when the project has no categories, after the commit and never inside it (ADR-0053), recording its attempt as a third `AiRefreshKind` (ADR-0060). Staff press Regenerate categories on any status but soft-deleted to replace the set from the current text. The model never writes to `categories`: Regenerate alone may propose one new category in an existing type other than Kind of work, shown as a form and created only when staff approve it through `createCategoryAs`, so the list stays small enough to curate. The run on submit and the backfill meter against no one's AI limit, and Regenerate meters as `categories`. Embeddings were rejected because a project's vector is written only once it is published. Decided 2026-11-12.

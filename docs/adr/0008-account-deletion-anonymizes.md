# Deleting an account anonymizes the row; the schema decides what else goes

The `restrict` foreign keys into `user.id` (comments, status history, edit logs, request lines) are audit records the row exists to anchor, so an account is never hard-deleted. The row keeps `deleted_at` with every personal column scrubbed, and what else goes is exactly what a real `DELETE` would cascade, read off the schema: every table whose key into `user.id` says `cascade` is deleted by user id, and a test pins that list so a new cascade edge without a matching delete is red. `set null` edges keep pointing at the row. Sessions and credentials go, and the scrubbed email frees the address for a fresh user. `/privacy` promises exactly this, so its copy and the deletion dialog move together. Deletion is refused while the person holds an item or has an approved request, and for the only admin; a ban is the tool for a real user who has to go.

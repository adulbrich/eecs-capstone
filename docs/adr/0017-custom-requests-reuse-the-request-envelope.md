# Custom requests reuse the request envelope, and an envelope holds one kind of line

A custom request, an ask for equipment the inventory does not hold, is an `inventory_requests` row with one `inventory_custom_lines` row per thing, rather than a table of its own. Both grouped tables, the staff queue and `/my/items`, group by the envelope, so one shape there means the group header renders one thing rather than a union it has to branch on, and the requester's note, the submitted date and the requester travel the same way for both kinds. An envelope holds either item lines or custom lines, never both; the standalone form at `/inventory/request` guarantees it, because nothing else writes custom lines and a borrow list writes only item lines. That is what makes a group action clean: on a borrow list it takes one pickup date for every line, on a custom request it takes nothing.

## Consequences

An `inventory_requests` row no longer implies an `inventory_request_items` row exists. Every query joining the two was checked when this landed and the three that mattered were changed: the admin overview tile counts envelopes with a pending line of either kind, and the two list reads run one query per kind and merge. A new join that assumes the old shape silently drops every custom request, which `docs/QUIRKS.md` records under Inventory. The items a fulfilled line produced are a join table, `inventory_custom_line_items`, with `RESTRICT` on the item, matching ADR-0006: an item that fulfilled a request can be retired but not hard deleted, because the fulfilment record is the point. The join table is also what lets `/my/items` file the hold a fulfilment created under the line that produced it rather than under "Assigned to you by staff", since mechanically the hold is an ordinary staff one.

# Sign-in limits are sized for a shared address, and brute force moves elsewhere

Better Auth's rate limiter keys a bucket on the viewer address and the path, and OSU wireless NATs students into shared public addresses, so a per-address number caps volume from a crowd and cannot protect a credential at any value. `src/lib/_internal/auth-rate-limits.ts` raises the paths where the number protects nothing to 60: `/sign-in/social`, which mints an OAuth state and redirects and since Better Auth 1.7 carries ONID as well as GitHub, so the two share one budget (#278), and the two code-entry paths, whose guess budget is per code (ADR-0047). `/email-otp/send-verification-otp` sits at 10, enough to slow bulk mail from one source, while the per-recipient cap bounds any one inbox. `/get-session` is not limited, because every page render calls it. Read every number as a budget between lulls, not a rate: a count clears only after a window with no accepted request, so a steady trickle still reaches the max. Decided 2026-09-21 in #535.

# Placement plugins convert to the standard CSV

Amended on 2026-10-04 by [#735](https://github.com/adulbrich/eecs-capstone/issues/735): a plugin may be chosen rather than detected. Custom mapping has no detection and claims no file; staff choose it with "Read as" or "Map columns", so the detection order below covers detected plugins only, and a chosen plugin passes its own branch of the contract test.

Placement has one standard CSV per dataset (projects, roster, bids), described in `src/lib/placement/formats.ts` and read by one parser each, and every other shape a source comes in reaches placement through a plugin that converts it into that CSV: Canvas's roster export, the Qualtrics bidding survey, pasted emails and pasted titles today, and whatever another program, college or contributor brings next. A plugin writes standard CSV text rather than parsed students or projects, so validation lives in one parser per dataset, staff can download what a plugin made and re-upload it without the plugin, and a plugin's own issues name rows in the file staff actually uploaded. A plugin is a module in `src/lib/placement/plugins/`, added to the registry by a pull request, and passes a contract test every registered plugin runs. The alternatives were plugins that emit the parsed model, which would spread validation across every plugin, and plugins staff upload as code at run time, which would run JavaScript nobody reviewed in the page that holds FERPA records ([ADR-0056](./0056-placement-runs-in-the-browser.md)); a mapping staff build in the page is data, not code, and is a plugin of its own (#735). The roster and the bids are stored as the file staff uploaded and converted on every read, as they were already parsed on every read, so a plugin that reads the project list sees it as it is now and a fix to a plugin reaches every saved workspace. Projects stay stored parsed, because staff edit them by hand afterward, so a projects plugin runs once at import. What this costs is a second step per read for converted files, which is small at a class's size, and a detection order that has to stay unambiguous: the standard format is tried first, then each plugin in registry order, and the contract test fails a plugin that claims a standard template or another plugin's source. Decided 2026-10-03 in #698 and #733.

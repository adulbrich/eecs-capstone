# A one-off ops script is plain `.mjs` and copies what it needs from `src/`

Anything run as a one-off ECS task is a `.mjs` under `scripts/`, named on the `COPY scripts/...` line in the `Dockerfile`, importing nothing but production dependencies. The runtime image installs with `npm ci --omit=dev` and ships `.output` without `src/`, so a TypeScript script has neither `tsx` nor a resolvable `#/lib`. The alternative, compiling these scripts into the image on every build, buys a single source of truth for logic that runs a handful of times ever, and costs a build step that every deploy pays whether or not anybody runs the script. We took the duplication instead. `import-legacy.mjs` was the first (it copies `NAMESPACE`, `uuidv5` and a filename from `import-legacy-images.ts`), `backfill-embeddings.mjs` the second (it copies the embedding source builder, the hash and the Bedrock request shape from `src/lib/`).

The cost is real and the mitigation is not optional: every copy gets a `MUST match` comment naming its original, and a parity test reads both files as text and compares the duplicated declarations, so drift fails the unit suite rather than production. Compare whole function bodies with whitespace collapsed rather than a sample of lines, and pin anything whose value is itself an input to stored data against a literal too, because an edit applied to both sides satisfies a copy-to-copy comparison while still re-keying every row. That comparison cannot strip comments or TypeScript annotations, so a declaration on the `src/` side that a parity test compares has to stay free of both, with its explanation in the JSDoc above it. `src/test/import-legacy-parity.test.ts` and `src/test/backfill-embeddings-parity.test.ts` are the two worked examples.

A script that needs the app's own modules, such as image processing or an existing writer, stays TypeScript and stays on a workstation. That is the honest split: `backfill-embeddings.ts` calls `refreshProjectEmbedding` and has nothing to keep in sync, and it can never run in production.

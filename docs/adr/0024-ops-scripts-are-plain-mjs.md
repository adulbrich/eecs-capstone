# A one-off ops script is plain `.mjs` and copies what it needs from `src/`

Anything run as a one-off ECS task is a `.mjs` under `scripts/`, named on the `COPY scripts/...` line in the `Dockerfile`, importing nothing but production dependencies. The runtime image installs with `npm ci --omit=dev` and ships `.output` without `src/`, so a TypeScript script there has neither `tsx` nor a resolvable `#/lib`. The alternative, compiling these scripts into the image, buys one source of truth for logic that runs a handful of times ever and costs a build step every deploy pays whether or not anybody runs the script; we took the duplication instead, and pay for it with a parity test rather than with care. A script that wants the app's own modules, such as image processing or an existing writer, stays TypeScript and stays on a workstation: `scripts/backfill-embeddings.ts` calls `refreshProjectEmbedding` and so has nothing to keep in sync, and it can never run in production. Decided 2026-09-15 in #427.

## Consequences

Every copied declaration carries a `MUST match` comment naming its original, and a parity test compares the two as text: `src/test/import-legacy-parity.test.ts` for `scripts/import-legacy.mjs`, `src/test/backfill-embeddings-parity.test.ts` for `scripts/backfill-embeddings.mjs`, and each test's `it` names are the authoritative inventory of what is pinned, so prose elsewhere points at it rather than listing it again. Three rules make those comparisons worth having: compare whole function bodies with whitespace collapsed rather than a sample of lines; pin anything that is itself an input to stored data against a literal as well, since an edit applied to both sides satisfies a copy-to-copy comparison while still re-keying every row; and keep a compared declaration free of comments and TypeScript annotations, because the comparison strips neither, which is why explanations live in the JSDoc above it. A `.mjs` also cannot reach a shared constant, so a set it filters on gets pinned against the `src/` constant, and a query feeding a copied function gets pinned against that function's input type.

# A one-off ops script is plain `.mjs` and copies what it needs from `src/`

Anything run as a one-off ECS task is a `.mjs` under `scripts/`, named on the `Dockerfile`'s `COPY scripts/...` line and importing only production dependencies, because the runtime image ships `.output` without `src/`, `tsx` or `#/lib`. Compiling the scripts into the image was rejected: one source of truth for code run a handful of times would cost every deploy a build step. The duplication is paid for with a parity test. A copied declaration carries a `MUST match` comment naming its original, and its parity test's `it` names are the inventory of what is pinned; `scripts/backfill-embeddings.mjs` with `src/test/backfill-embeddings-parity.test.ts` is the example. Compare whole bodies with whitespace collapsed, keep a compared declaration free of comments and type annotations, and pin anything that feeds stored data against a literal too, since an edit to both copies passes a copy-to-copy comparison. A script that needs the app's own modules stays TypeScript on a workstation. Decided 2026-09-15 in #427.

# The last AI attempt is recorded per project

Each project's last attempt at its social summary and at its embedding is a row in `project_ai_refreshes`, keyed by project and kind, so staff can tell an output that failed from one nobody tried (#631). The automatic writers, Regenerate and Recompute record `updated`, `superseded` or `failed` with an `automatic` or `staff` trigger, keeping the later stamp; `skipped` and `manual` record nothing, and `unchanged` retires a failure, since the stored output is current. A sweep of stale hashes was rejected as answering the operator in aggregate, which #548's alarm does. `ai_review_usage` was rejected because it counts model calls for the limiter, and a `superseded` refresh is a paid call that stored nothing; `project_edit_log` because it needs an editor. Only the last attempt is kept, since each output's `*_updated_at` carries the last success. This amends ADR-0053: the refresh log line is no longer the only record of a refresh. A lost record write leaves no row, so the panel says "on record", not "never". The `.mjs` sweeps write without recording, so the view drops an attempt older than the output. Decided 2026-10-05.

# The last AI attempt is recorded per project

Each project's last attempt at its social summary and at its embedding is a row in `project_ai_refreshes`, keyed by project and kind and overwritten by the next, so staff can tell an output that failed from one nobody tried (#631). The automatic writers, Regenerate and Recompute record `updated`, `superseded` or `failed` with an `automatic` or `staff` trigger; `skipped`, `unchanged` and `manual` are not attempts and record nothing, so no row means never attempted. A periodic sweep of stale hashes was rejected: it answers the operator in aggregate, which the alarm from #548 already does, not staff looking at one project. `ai_review_usage` was rejected because it counts model calls for the limiter and the users page, and a write outcome is not a call (a `superseded` refresh is a successful call that stored nothing), and `project_edit_log` because it needs an editor and records edits. Only the last attempt is kept, since each output's own `*_updated_at` carries the last success. This amends ADR-0053: the refresh log line is no longer the only record that a refresh ran. The production `.mjs` sweeps write outputs without recording, which the view absorbs by dropping an attempt older than the stored output. Decided 2026-10-05.

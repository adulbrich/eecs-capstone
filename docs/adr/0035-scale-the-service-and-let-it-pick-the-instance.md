# Scale the service, and let the task count pick the database instance

The app service autoscales between `app_min_tasks` and `app_max_tasks`, target tracking average CPU at 50%, with 1024 MB per task and the deployment circuit breaker rolling back; the floor is above one because ECS takes 60 to 90 seconds to replace a crashed task. Memory was the binding resource, but a Node heap grows to fill what it is given and returns it slowly, so a memory policy adds tasks and never removes them: memory is answered by the task size and CPU is the scaling signal, which the #524 load test confirmed. The database moved to `db.t4g.small` rather than the pool shrinking, because the task count sets the connection budget (ADR-0034) and RDS CPU was never the constraint. The deploy workflow passes no `--desired-count`, which would reset the fleet on every deploy. Decided 2026-09-20 in #522.

# A fact that is a column on `projects` never also becomes a category

A category classifies a project by something the schema does not already record: a field, a technology, an industry. Whether a project is sponsored or student proposed is a column, `isSponsored` or `studentProposed`, that the form sets and the listings filter on, so a category carrying the same fact can only agree with the column or contradict it; the seed's three `project_type` categories went in #374, and `scripts/seed-dev.ts` seeds `field`, `technology` and `industry` only. Dropping the columns for categories was rejected, because a column is required, typed and validated and a category is a tag staff must remember to apply. A new fact about a project is a column with a filter, and a proposal for a category that duplicates one is declined by pointing here. Decided 2026-09-14 in #374.

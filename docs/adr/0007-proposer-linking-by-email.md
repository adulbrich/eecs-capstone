# Proposers link by email, `proposer_id` is canonical, and only a verified address claims

A project's proposer is an account id when one exists and an email address until then: email is the link key because staff propose projects for people who have not signed up, and the id is the source of truth once they have, resolved from the address on every write and never accepted from the client. An unlinked project is claimed only on proof of the address: the create hook, which a code sign-up and OAuth both reach with the address proved, a redeemed code on a row that existed unverified, and ONID taking an address off an unproven row (ADR-0045). Claiming on registration alone would let anyone take a colleague's projects by signing up at their address, so a new claim path must name its proof. Deleting an account keeps `proposer_id` set, so a re-registered address cannot reclaim, and the proposer email is private to staff.

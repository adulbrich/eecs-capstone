# A save does not wait for its AI refresh

Saving, publishing, archiving or restoring a project that ends published or archived starts its embedding and social summary refresh through `refreshProjectInBackground` in `src/server/_internal/project-refresh.ts` and returns without waiting, because a stalled Mantle call once held a committed save's response for 301 s. Timeouts bound the work instead: 60 s on the Mantle fetch, which also caps the AI review and the scope assessment, and 30 s on Titan. Refreshes were already best effort, and the backfill scripts sweep a stale hash. A refresh writes only while the row still carries the text the model was shown (`rowStillReads`), so with saves no longer serialized the one that read the current text lands and a loser reports `superseded`. Each refresh logs one line with both outcomes and its duration. Integration tests read what a refresh wrote only after `settleProjectRefreshes()`. Decided 2026-09-23.

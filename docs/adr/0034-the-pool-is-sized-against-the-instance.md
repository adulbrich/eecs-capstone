# The pool is sized against the instance, and traffic writes get their own

`src/lib/_internal/db-pool.ts` sizes the app pool against the database instance rather than the task: `CONNECTION_BUDGET` holds 45 connections per task, 5 more per task for the site traffic writer and 10 for a one-off script against the 220 usable on `db.t4g.small` at the task ceiling, and `src/lib/__tests__/db-pool.test.ts` fails when the sum overruns it. An idle client costs a task about 0.11 MB, so the instance's connection ceiling is what binds. A 5 second acquire timeout makes an exhausted pool fail visibly, because `/api/healthz` never touches the database and an unbounded wait hangs every page while the task stays green. The traffic writer, `src/db/traffic.ts`, is the one exception to one pool per process, so a flood of anonymous writes queues on its own 5 and drops an event rather than wait. Raising the pool, the task ceiling or the traffic share keeps the inequality true or changes the instance. Decided 2026-09-20 in #521.

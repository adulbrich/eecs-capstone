# A preload is kept only where no form seeds from the loader

`src/router.tsx` keeps `defaultPreloadStaleTime: 0`, so every hover on a link refetched that page's loader, and none of the loaders here go through TanStack Query, which is what the `0` is for (#762). A route may set `preloadStaleTime` up to 300,000 ms, the default `preloadGcTime`, so that a click reuses the hover's fetch, but only if its page seeds no form from loader data. This amends [ADR-0029](./0029-a-revisit-waits-for-its-loader.md), which covers revisits: a click within the window mounts on the preloaded frame and the blocking reload never runs, so a class A seed there could save values up to five minutes old over a colleague's edit. `StaffProgramSection` stopped seeding from the project page's loader and reads its own record through `getProjectPrograms` to qualify. A save that navigates to a page it changed clears that match first, and a code sign-in clears every cached match. `/projects` and `/projects/$projectId` keep a preload for five minutes. A viewer who hovered a link up to five minutes before a project was published or edited can see it as it was. A route that starts seeding a form from its loader drops the window or the seed; `src/test/loader-seed-scan.test.ts` fails when a `CENSUS` reason names a page that keeps one. Decided 2026-10-06.

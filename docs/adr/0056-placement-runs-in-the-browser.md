# Placement runs in the browser

Staff place students with a tool at `/admin/placement` that parses the bids, solves the placement and keeps the workspace in the staff member's own browser; no bid, comment or placement reaches the server. A bid carries a student's name, email, reasons and the classmate they would rather avoid, all FERPA education records, and keeping them off the server means no table to secure, retain, back up, anonymize (ADR-0008) or leak through a log. #33's in-app bidding into `project_bids` and `project_assignments` was the alternative, and closed unbuilt because programs run bidding differently. The cost is sharing: two staff cannot work one placement at once, a workspace moves between machines only as an exported file, and it lasts as long as that browser's storage. The one server call reads a program's published projects. The solver is HiGHS compiled to WebAssembly and run in a Web Worker. Decided 2026-09-25 in #644.

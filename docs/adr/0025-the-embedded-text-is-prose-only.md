# The embedded text is the project's own prose, not its categories or its program

`buildProjectEmbeddingSource` builds the string from the seven text fields a proposer writes, title through license restrictions, and nothing else. Its categories and its program used to be two more sections and are now left out. Both are already exact filters on the listing, `categoryIds` as a subquery requiring every selected category and `programId` as an equality, so embedding them put a second fuzzy copy of a filter the reader can already state precisely; the category vocabulary is generic enough ("Web Development", "Robotics", "Data Science") that a project carrying a tag almost always says so in its own description, so the section mostly repeated text sitting two lines above it; and a course identifier like `CS46X-CORVALLIS Capstone (3-term)` is not language, so it contributes close to nothing to a similarity comparison while taking room from text that does. The other side of that comparison is the reader's free-text interests, which carry no taxonomy and no labels at all, so a section with no counterpart there could only add noise. The alternative, keeping them and sorting the category read to make the hash reproducible (#457), was not taken: it fixed the symptom and left the section earning nothing. Decided 2026-09-17 in #461.

## Consequences

Editing a project's categories or its program no longer changes its embedded text, so `refreshProjectEmbedding` returns `"unchanged"` for those edits, which is correct rather than a miss. `refreshProjectEmbedding` and `scripts/backfill-embeddings.mjs` each lost two queries per project and the `.mjs` lost two copied declarations, so what crosses the image boundary shrank; `src/test/backfill-embeddings-parity.test.ts` pins the absence on both sides, because reintroducing a section on both at once is the one edit a body comparison would pass. #457 is closed by this rather than fixed: there is no category read left to disagree about. Changing this string changes every stored `embedding_source_hash`, so the sweeper re-embeds every project once at one paid Bedrock call each, which is the cost of any edit here and the reason the sections were weighed rather than tuned.

# A log line takes a string, never an error object

Every `catch` logs `redactQueryError(error)` from `src/lib/_internal/redact-query-error.ts`, a string, never the error object, because an error can carry a credential: `DrizzleQueryError` keeps the bound parameters, such as a session token, on `.params` and interpolates them into `message`, so logging `error.message` leaks too. A helper returning a string is enforceable, since no console method walks a string back into an object. On the auth path, `onAPIError: { throw: true }` in `src/lib/auth.ts` keeps Better Auth's router from logging the raw object, and `handleAuthRequest` catches the throw, logs it redacted and returns the same 500. Turning Better Auth's logger off was rejected because it removes the signal with the leak, and setting `level` on it routes a copy around the redaction. The cost is diagnostic: a redacted line keeps the SQL but not the values. `src/lib/__tests__/redact-query-error.test.ts` pins the hazard as well as the fix. Decided 2026-09-21.

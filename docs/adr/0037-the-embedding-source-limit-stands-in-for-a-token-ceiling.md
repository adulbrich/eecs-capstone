# The embedding source limit is a character cap standing in for a token ceiling

`EMBEDDING_SOURCE_LIMIT` truncates the embedded text at 20,000 characters to stay under Titan Text Embeddings V2's ceiling of 8,192 tokens. No character count guarantees a token count: the densest text measured, pasted links in legacy rows, ran 2.59 characters per token, so 20,000 leaves about 6 percent margin and sits just under the project form's own combined cap. Truncating in the source builder keeps `embeddingHash` over exactly what was embedded; retrying a rejection on shorter input inside `bedrockEmbed` was rejected because the stored vector would stop matching its hash. Changing the number re-embeds every row longer than the smaller value, at one paid call each. Text denser than 2.44 characters per token still overflows and fails as an oversized row does. `src/lib/__tests__/embedding-source.test.ts` pins the arithmetic, and the backfill parity test pins the literal across its three copies. Decided 2026-09-20.

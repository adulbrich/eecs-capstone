# `sourcing` rather than `approved` on a custom line, and no `returned`

A custom line has the same five slots as a request line, with two words swapped on purpose. Its live-yes state is `sourcing`, not `approved`, because approving a request line reserves a physical item and a custom line has none, so one word would name a promise and a reservation in a queue that shows both. Its success state is `fulfilled`, not `returned`: a borrow succeeds when the thing comes back, an acquisition when it exists. A custom line may be rejected from `sourcing`, unlike a request line, because an order can fall through. `INVENTORY_CUSTOM_LINE_STATUSES` is its own tuple and `pgEnum`, and the queue's filter is the union of both tuples. `sourcing_note` and `outcome_note` are separate columns so fulfilling never overwrites what sourcing said, and neither reuses `review_comment`, which the requester's projection hides.

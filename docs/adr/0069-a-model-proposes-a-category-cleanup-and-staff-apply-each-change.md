# A model proposes a category cleanup and staff apply each change

The category list only grows, so staff press Propose a cleanup on `/admin/categories` and one Mantle call over every project category, given its definition, both usage counts, its creation date and up to five published titles, proposes merges, renames, moves and retirements in a closed tool schema over handles, with no create and no split (#857). Nothing is stored and nothing changes until staff tick a change and apply it. Each change applies in its own transaction against the rows as they are then, and is refused when a category it names differs at all from what the proposal saw, so a hand edit made in between wins and the other changes still apply. Kind of work gets no handle and is in no type enum, and apply checks the same again, since the change arrives from the browser. The call uses the categorizer's model and effort and meters under `categories` beside Regenerate, with no project, so no new setting reaches the task definition. Applying writes no edit log row, as setting a project's categories writes none; each apply logs one line. Decided 2026-11-12.

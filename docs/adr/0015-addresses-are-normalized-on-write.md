# Email addresses are lowercased on write, in the four columns this app owns

`inventory_items.current_holder_email`, `inventory_item_status_history.holder_email`, `projects.proposer_email` and `projects.mentor_email` are trimmed and lowercased before they are stored, by `normalizeEmailAddress` in `src/lib/email-address.ts`. The alternative, folding case at each comparison, cannot use a plain btree index and makes every new read site another place to remember the rule. The cost: the stored address no longer keeps the case a person typed, and `updateProjectMentorshipAs` logs through `diffRowFields`, so the edit log records the normalized address and an edit changing only case finds no changed field and writes no row. Reads against Better Auth's `user.email` keep their `lower()`, because that column's lowercasing is a library's internals that an upgrade could change.

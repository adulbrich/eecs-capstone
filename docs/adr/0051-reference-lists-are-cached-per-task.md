# The listing's filter options are cached per task, for a minute

The project listing reads its category and program filter options through `listProjectFilterOptions`, which caches the promise in process for `REFERENCE_LIST_CACHE_TTL_MS`, 60 seconds in production, because the pool fails first under a term start burst (#558) and two of the loader's three reads were tables that change a few times a term. A staff write clears the cache only on its own task, so another task can show a stale filter for up to a minute; shared invalidation would need a channel that itself costs connections. The cache sits in front of the listing only, because inside `listCategoriesImpl` it left staff pickers missing a just-created category, and staleness in an edit form is a defect. The TTL is off unless `infra/ecs.tf` sets it, so browser suites run uncached and the integration suite clears it in `resetDatabase()`. Every new writer to `categories` or `programs` calls `clearAllReferenceListCaches()`. Decided 2026-09-22.

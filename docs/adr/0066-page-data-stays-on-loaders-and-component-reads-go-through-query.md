# Page data stays on loaders, and component reads go through Query

The app loaded data three ways: route loaders for each page's data, TanStack Query for the bell, bookmarks, the borrow list and similar projects, and hand-written `useEffect` fetches in components, which had no cache and no protection against a late answer for a page the component had moved off. Moving every loader onto Query was weighed and declined (#767, first comment): load is not a driver (the 2026-09-25 term-start peak ran at 31% CPU, p95 32 ms), the five class A seeds of [ADR-0029](./0029-a-revisit-waits-for-its-loader.md) would need reworking, and `ensureQueryData` returns stale cache, so each of the fourteen `router.invalidate()` sites would need a matching invalidation or a save would silently stop showing. Page data stays on loaders and the router's cache; a read a component makes for itself after the page appears goes through `useQuery`. Hand-written fetches in components are removed as their readers move (#767, #768). A save on one page does not refresh another page's cached data at once. Revisit for the routes involved if post-#762 call counts show page data dominating in a way router options cannot fix, if a feature needs cross-page refresh, or if staff report cross-page staleness. Decided 2026-10-06.

# Listing filters sit in a left aside from `xl`, and in a sheet below it

A listing page keeps its search on top at every width, and puts the controls that narrow the list in a left aside from 1280px and in a left `Sheet` below that, opened by a "Filters" button that carries the count of what is on. Sort and the card/table toggle stay beside the search, because they order and display rather than narrow. Before this, `/projects` stacked a filter card above the list so the first project sat a screen down on a phone, and `/admin/projects` put nine fixed-width controls in the table's toolbar slot, wrapping to three rows at 1280px. This adds a third responsive tier to a design system that had deliberately kept two; the tier is `xl` rather than `lg` because the card column is 896px, the aside 18rem, and with the gap and page padding that is 1280 exactly, so the cards never shrink to make room. The admin filters left `AdminDataTable`'s `toolbar` slot rather than the table growing a filters slot, because the grouping mode is meant to be that component's one extension. Decided 2026-09-12 in #350.

## Consequences

`ListingLayout` in `src/components/listing-layout.tsx` is the one component that carries `xl:` layout classes, a route passes at most its width pair, and `docs/UI-CONVENTIONS.md` names both as the exception. The narrowing form renders twice, in the aside and in the sheet, so a filters component must be safe to mount twice and must give every control `w-full`. Switch labels shortened to one line under a legend, which changed their accessible names and the two accessibility tests that used them. The public listing's table mode is bounded to the card column below `xl` instead of running full width. `/inventory` and `/admin/inventory` followed in #352, so all four listings render through the shell.

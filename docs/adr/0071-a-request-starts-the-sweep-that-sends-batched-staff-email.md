# A request starts the sweep that sends batched staff email

A proposer's edit to an approved or published project stays live at once, and the staff inbox gets one email per burst of them, sent 30 minutes after the last save or 3 hours after the first (#839). No save can send it, since it waits on saves that have stopped. The server entry starts a sweep after a request, at most once a minute per task and single flight; the edit log rows are the queue. This keeps ADR-0005: no cron, no queue service, no second process, no timer between requests. Not taken: a `setInterval` in each task, the timer ADR-0005 rules out, and a scheduled ECS task, the second process. The load balancer checks `/api/healthz` every 30 seconds, so a task sweeps each minute with no visitors. The claim runs under a transaction-scoped advisory lock, so two tasks never split one burst. The send runs with no transaction open, and a claim left unstamped is taken again after ten minutes, so delivery is at least once, which ADR-0019 prefers to a lost email. A crash between send and stamp sends one twice. Decided 2026-11-17.

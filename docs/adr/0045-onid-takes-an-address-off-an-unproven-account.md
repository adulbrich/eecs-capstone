# ONID takes an address off an unproven account, deleting its password

`onidUserInfo` in `src/lib/auth.ts` calls `releaseUnverifiedAddress` before Better Auth decides whether to link: when the address is held by an unverified row with nothing but a `credential` account, that row loses the password and its sessions, gains `email_verified` and takes the ID token's display name, keeping everything else attached. Without it, a squatter's unverified password row made the owner's first ONID sign-in fail with `account not linked`. The credential is deleted in the same transaction and before the flag is written, because the reverse order failing midway leaves a verified account whose password a stranger knows. This is the OAuth counterpart of Better Auth's `revokeUnprovenAccountAccess`, which its OAuth link path never calls, but stricter: `addressProofRefused` in `src/lib/address-proof.ts` refuses a row another provider is linked to and one under an active ban. Projects are claimed explicitly, since no verification hook fires here. Password accounts stopped in #576, so this serves older rows. Decided 2026-09-21 in #554.

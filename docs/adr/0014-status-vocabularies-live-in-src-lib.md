# The status vocabularies live in src/lib, not in the schema

Each status vocabulary used to be written out more than once, as a `pgEnum` in `src/db/schema.ts`, as a hand-written union in a `src/lib` module, and again in every route that filters by it, with nothing linking the copies: a value added to one and not the others was either a row Postgres accepts that the app cannot name, a status the app hands to a column that rejects it at runtime, or a status no filter can select. `src/lib/vocabularies.ts` now holds each one once as an `as const` tuple. The schema passes the tuple to `pgEnum`, and `project-workflow.ts`, `inventory-visibility.ts` and `inventory-workflow.ts` derive their unions from it with `(typeof T)[number]`.

The direction is the decision. Deriving the unions from `enumValues` the way `src/server/_internal/categories.ts` does would have been less code, but it makes every client-safe module that names a status import `src/db/schema.ts`, and with it `drizzle-orm`, into the client bundle. Putting the tuples in `src/lib` instead means the dependency runs the other way, `src/lib` imports nothing, and no bundle audit is needed to keep it that way. `RequestLineOutcome` stays hand-written because it is a proper subset of its column (`pending` and `approved` are line statuses a release never writes); a `Part extends Whole` constraint holds it to the column, so renaming a value in the tuple fails to compile at the declaration.

The filter vocabularies derive from the tuples too, since they are the same set: `["all", ...PROJECT_STATUSES]` and `[...INVENTORY_REQUEST_ITEM_STATUSES, "all"]` add only the sentinel a filter needs for "no filter", and `/admin/inventory` uses `ACTIVE_STATUSES`, which is the vocabulary minus `retired` because `retiredOnly` is its own filter.

The pairing assertion this replaced is gone, because it can no longer fail. What was `src/lib/__tests__/workflow-vocabularies.test.ts` is now `workflow-totality.test.ts`, keeping the half that deriving the types does not give you: that the tables keyed by these vocabularies answer every input, and that the project transition graph is connected.

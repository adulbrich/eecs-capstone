# A comment is edited in place, and the reply is what freezes it

An author may rewrite their own comment, and the row keeps no prior text: `project_comments` gains only `edited_at`, so the page can say the words moved but not what they were. That relaxes ADR-0008's treatment of comments as audit records, and the lock is what makes it safe: once anything replies to a comment, internal or not, it is frozen. The `(edited)` marker and the email, which went out with the original words, stand in for a history; a version table would cost a projection, a retention answer and a reader for a feature whose case is a typo. `updateCommentAs` is the only writer: the editor must still be in the thread and must be the author, staff included; the reply lock rides the `UPDATE` as a `NOT EXISTS`, so a reply landing mid-edit stops it. An edit notifies nobody, `is_internal` is not editable, and the lock reaches the client as `hasReply`, computed before `filterCommentsForViewer`. Decided 2026-09-18 in #503.

# A revisit waits for its loader rather than painting the last visit's data

`src/router.tsx` sets `defaultStaleReloadMode: "blocking"`, so a revisit waits for its reload instead of painting cached `loaderData` and revalidating behind it. Under the default, with `defaultStaleTime` 0, leaving a save landed on pre-edit data, and a form seeded with `useState(record.field)` kept it and could save it back over a colleague's edit. `router.invalidate({ sync: true })` before each `navigate()` also works and was rejected because every call site has to remember it. The cost is that a revisit waits like a first visit, with nothing marking the wait. Seeds from loader data with no key and no resync (class A) rely on this option by decision; the census of every once-only seed, in classes A to D, is `CENSUS` in `src/test/loader-seed-scan.test.ts`, which also fails if the option is reverted or a route sets `staleReloadMode`. The remedy then is one resync effect per seed with a primitive dependency, as `src/components/instructor-manager.tsx` does, and for a TanStack Form an effect that calls `form.resetField` on each field whose default moved and whose value still equals the old one. Decided 2026-09-17 in #474.

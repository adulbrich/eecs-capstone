# A revisit waits for its loader rather than painting the last visit's data

`src/router.tsx` sets `defaultStaleReloadMode: "blocking"`, so a stale route match waits for its reload instead of painting cached `loaderData` and revalidating behind it. `defaultStaleTime` is 0, which makes every revisit stale, and the default `"background"` meant every navigation away from a save landed on a frame built from pre-edit data: a list flashed the old row, and an edit form whose inputs are `useState(record.field)` seeded from that frame and never recovered, because a `useState` initializer does not re-run when props change. That second half is a write risk rather than a display one, since a staff member reopening such a form sees stale values and saves them back over a colleague's edit. The alternative, `router.invalidate({ sync: true })` before each `navigate()`, was measured and works, and was rejected because it has to be remembered at each of seven call sites and the eighth silently restores the bug; plain `invalidate()` fixes nothing here, because it revalidates in the background and its promise resolves before any reload lands. The cost is accepted and felt by real users: a revisit now behaves like a first visit, the previous page stays on screen until the loader resolves, and the app sets no `defaultPendingMs` or `defaultPendingComponent`, so nothing marks the wait until the router's 1s default. Decided 2026-09-17 in #474.

## Consequences

Seeding `useState` from loader data is only correct while the router blocks, so a route that does it keys the child holding those seeds on the record, and the two that did are keyed now: `/admin/programs/$programId` on `String(program.updatedAt)`, which `updateProgramAs` bumps, and `/admin/categories/$categoryId` on its seeded values, because the `categories` table has no `updatedAt` and a column added to feed a React key would be a schema change in service of a render detail. `remountDeps` cannot serve that purpose at all: it sees `search`, `params` and `loaderDeps`, never loader data. The stay-on-page pattern is unaffected, because a component that stays mounted across `await router.invalidate()` re-renders from the new data and involves no seed. A route that measurably needs the instant paint can opt back in with `staleReloadMode: "background"` on itself, and then owns the freezing problem for any seed it holds; none does today. The heaviest loader here, `/admin/projects`, returns 28 KB across two server functions in about 55 ms, so the wait is the round trip rather than the query, and a `defaultPendingComponent` is the answer if that round trip ever reads as a hang.

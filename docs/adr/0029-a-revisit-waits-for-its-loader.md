# A revisit waits for its loader rather than painting the last visit's data

`src/router.tsx` sets `defaultStaleReloadMode: "blocking"`, so a revisit waits for its reload instead of painting cached `loaderData` and revalidating behind it. Under the default, leaving a save landed on pre-edit data, which a form seeded with `useState(record.field)` kept and could save back over a colleague's edit. `router.invalidate({ sync: true })` before each `navigate()` was rejected because every call site must remember it. The cost: a revisit waits like a first visit, and nothing marks the wait. Seeds from loader data with no key and no resync (class A) rely on this option by decision: a key on `updatedAt` remounts on any write, and a key on the seeded values remounts the whole subtree and drifts when a field is added, both discarding open edits. `CENSUS` in `src/test/loader-seed-scan.test.ts` classes every once-only seed A to D and fails if the option is reverted or a route sets `staleReloadMode`. The remedy then is one resync effect per seed with a primitive dependency, as `instructor-manager.tsx` does, and for a TanStack Form an effect calling `form.resetField` on each field whose default moved and whose value still equals the old one. Decided 2026-09-17 in #474.

# One named `*ForCurrentUser` wrapper per action, over an `*As(viewer, ...)` seam

Every server-side action is one `createServerFn` wrapper calling one `*ForCurrentUser` function, which resolves the viewer and delegates to an `*As(viewer, data)` seam that takes the viewer explicitly; an implementation that needs no viewer object is `*Impl`, with the authorization in the wrapper above it. Integration tests call the seam with a seeded user and never cross `requireUser()`, which reads a request context the harness cannot provide, and `src/server/__tests__/seam-convention.test.ts` fails a wrapper that has no seam. Collapsing the wrappers into one generic `withCurrentUser()` adapter was rejected: a named function per action is a grep target and an adapter is none, and the seam beneath, not the wrapper, is the layer tests cross.

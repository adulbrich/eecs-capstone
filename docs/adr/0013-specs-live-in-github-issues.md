# Specs live in GitHub issues

All work starts from a `ready-for-agent` or `ready-for-human` issue carrying an agent brief (current behaviour, desired behaviour, key interfaces, acceptance criteria, a table of which fields are public and who edits them) and ends in a pull request that is the plan, reviewed by `mattpocock-skills:code-review` until a pass raises nothing unanswered. The issue is the spec for a large feature as much as a bug. `docs/superpowers/` holds the specs and plans of features built before 2026-10, kept for reference, and is not a workflow to start new work in. Briefs name file paths on purpose: here they are the grep targets the codebase is organized around, and issues are picked up within days.

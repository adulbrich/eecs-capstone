# A pickup place is what staff typed

An approval gives the requester a pickup window, a pickup place and a pickup note, kept on the request line and, for the current hold, on the item (`current_pickup_*`), as the pickup deadline already was. The place is a copy staff chose, never a read of `inventory_items.location`: the location is where an item is stored and stays staff only, while the place is usually the instructor's office. A one-item dialog (the queue's Approve, the item page's Reserve) copies the location in for staff to keep or replace, under a hint saying so; Approve all starts blank and names no location, because a batch's items sit in different places and none is where the student goes. The window is a day plus optional From and To in `America/Los_Angeles`, composed on the server from strings, and its end is the pickup deadline, so the overdue rule is unchanged. Rejected: letting a requester with an approved line read the location, which leaks storage detail and shifts when the item is edited; a free-text window nothing can check. A release or checkout clears the item's terms and the line keeps them, and any new path that reserves to a person takes the place from staff, not the item. Decided 2026-10-23 in #799.

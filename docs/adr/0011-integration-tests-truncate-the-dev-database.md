# Integration tests run against the dev database and truncate it

The integration suite uses the same `DATABASE_URL` as development and truncates every table before each test, so `npm run test:integration` deletes dev data and `npm run db:seed:dev` puts it back. A dedicated `eecs_capstone_test` database behind a `TEST_DATABASE_URL` is the intended end state and is not built; one database is the accepted trade for a suite that needs no second container and no second migration run. Reseed after an integration run before a browser suite, and apply a new migration before the suite passes; the smoke and accessibility suites share the database and sweep their own rows by prefix.
